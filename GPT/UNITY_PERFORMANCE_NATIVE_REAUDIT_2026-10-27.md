## Главный вывод

Браузерный UI/Canvas и JS-подобный слой не являются активным Android-путём. Но «всё сделано штатными высокоуровневыми компонентами Unity» тоже неверно. Бой использует собственный C#-компоновщик поверх Unity Mesh/Material/CommandBuffer/RenderTexture. Нашими остаются организация кадра, часть геометрии и анимации, управление частицами, поиск целей, фазы симуляции и снимки сохранений.

Эти категории нельзя смешивать: собственная игровая логика нужна; использование Mesh/CommandBuffer уже является нативной Unity-отрисовкой; передача управления URP, ParticleSystem или ObjectPool может убрать конкретную инфраструктурную работу, но сама по себе не гарантирует ускорение и идентичность изображения.

## Подтверждённые механизмы нагрузки

Приоритет означает порядок инженерной работы, а не измеренную долю времени кадра на новой APK.

### P1 — полноразмерное наложение каждой локально размытой тени

`Presentation/NativeWorldSurface.cs:186–226`, `Resources/EchoSphere/SourceCanvasShadow.shader:24`.

Маска и два Gaussian-прохода уже ограничены `ShadowArea`; веса кэшируются. Однако последующий `_commands.Blit(..., _target, ...)` покрывает весь целевой буфер мира **для каждой тени**, включая cache-hit. Шейдер возвращает нулевую альфу вне области, но геометрия прохода не ограничена прямоугольником тени. Это не прежнее полноэкранное размытие: остался полноразмерный этап смешивания, создающий потенциальный fill-rate/overdraw и переключения render target.

Исправление-кандидат: рисовать ровно прямоугольник конечной тени через mesh/viewport/scissor с правильным преобразованием UV. Сохранить полное ядро, смещение, MSAA, порядок прозрачности и normal/additive/screen blending. Счётчик `ShadowPassCount` сейчас считает промахи размытия, **не все физические GPU-проходы**; оценивать успех только по нему нельзя.

### P1 — мир вручную проходит через отдельную текстуру и копирование

`Runtime/EchoSphereSourcePresentation.cs:169–208`, `Presentation/NativeWorldSurface.cs:66–92,174–232`, `Presentation/NativeRunDocument.cs:38–39,68–79`.

На каждом боевом LateUpdate: построение списка команд → ExecuteCommandBuffer → MSAA target → Graphics.Blit в UI texture → UI Toolkit Image. Камера имеет `cullingMask=0`. Этот путь обходит обычное управление сценовыми Renderer и автоматическое отсечение объектов камерой. Вызов продолжается и под паузой; часть визуальных часов/эффектов может требовать обновления, поэтому замораживать всё без проверки нельзя.

Это крупный оставшийся инфраструктурный слой. Целевой кандидат — URP ScriptableRendererFeature/RenderGraph для порядка проходов и владения transient-ресурсами; затем, при необходимости, непосредственная отрисовка мира камерой под UI. Перенос не должен начинаться с массового добавления GameObject на каждую линию. Сначала сохранить существующие меши, шейдеры и прозрачный порядок. Полноэкранный промежуточный target может остаться необходимым для конкретного смешивания/фильтра.

Предыдущая изоляция в Editor показала, что удаление мира НЕ устраняло прежний основной stall UI-теней. Поэтому именно этот слой нельзя без нового измерения объявить причиной прежних 1–2 FPS.

### P1 — подготовка невидимых врагов и изменяемых контуров

`Runtime/EchoSphereNativeFrame.cs:49–59`, `Presentation/NativeWorldEnemyView.cs:61`, `NativeWorldCreatures.cs:44–48,103–126`, `NativeWorldShapes.cs:94–108`.

Цикл передаёт в DrawEnemy всех живых врагов без проверки пересечения экрана; DrawEnemy готовит анатомию, статусы, свечения и команды. GPU clipping не отменяет эту CPU-работу. Статические контуры и кости фиксированной длины уже кэшируются. Изменяющиеся контуры и длины штрихов всё ещё могут вызывать Vector Graphics tessellation; массивы входных контуров также создаются до проверки кэша.

Следующая работа: консервативное визуальное отсечение до геометрии с полными границами свечения, конечностей, boss telegraph и подписей. Не останавливать симуляцию/позу невидимого врага. Для реально изменяемых форм — retained mesh с обновлением вершин либо проверенный 2D rig; не заменять всю анатомию Animator только ради названия Unity.

### P1 — создание и уничтожение объектов на каждом выстреле/частице

`Runtime/EchoSphereRuntime.cs:2333–2346`, `EchoSphereSourceLoop.cs:106–114`, `SourceParticle2D.cs:17–25`, `ProjectileAgent.cs:83–128`, `ISourceSimulationAgent.cs:12–24`.

Снаряд создаёт GameObject и компоненты; истечение жизни/попадание уничтожает его. Каждая SourceParticle создаёт GameObject, SpriteRenderer и компонент. При этом визуальная камера эти SpriteRenderer не рисует, а SourceParticle всё равно обновляет их цвет; реальное изображение частицы собирает native world. Регистрация частиц сканирует общий список и отдельно удаляет избыток. Это подтверждённое обслуживание невидимого представления и churn, но не доказанное двойное рисование на GPU.

Первый кандидат — UnityEngine.Pool.ObjectPool для снарядов/частиц/подбираемых объектов. Нужны полноценные reset/release, сохранение порядка регистрации, очистка hit-ID, владельцев и lifetime. Instance ID после reuse нельзя считать идентификатором нового рождения: добавить/проверить отдельную генерацию для связанных кэшей. SourceParticle входит в сохранения, поэтому менять формат и терять состояние запрещено.

ParticleSystem подходит прежде всего для декоративного слоя. Исходное затухание скорости `_velocity *= .95f` происходит за шаг, а не за секунду; стандартная drag-кривая не идентична автоматически. Сохранить точный шаг, начальные параметры, порядок RNG и восстановление. Боевые снаряды оставлять игровой моделью, ParticleSystem не должен определять попадания.

### P2 — визуальная проекция сети пересоздаётся каждый кадр

`Runtime/EchoSphereNativeNetwork.cs:26–42`, вызов из `EchoSphereNativeWorldViews.cs:9` / `EchoSphereNativeFrame.cs:49`.

`Where/Select/ToArray/ToList`, массивы связей и узлов, объекты семи формаций создаются на активном пути рисования. При этом `NativeNetworkAnalysisCache` уже сравнивает точные входы и переиспользует результат анализа. Нельзя снова писать «анализ всегда пересчитывается каждый кадр».

Сделать retained typed presentation buffers: топологию обновлять при изменении, координаты/charge/pulse — своевременно. Для этого не нужны ECS или новый движок сети.

### P2 — полный перебор объектов в нескольких фазах и запросах целей

`Runtime/ISourceSimulationAgent.cs:28–42`; `EchoSphereRuntime.cs:2151–2163,2307–2330`; `ProjectileAgent.cs:83`.

FindAll в фазах уже заменён переиспользуемыми списками, но каждая фаза делает RemoveAll и повторный обход общего списка. Поиск ближайшего/попадания сканирует врагов; радиусный запрос дополнительно создаёт List. Нагрузка растёт с количеством снарядов и врагов.

Кандидаты: поддерживаемые списки фаз, пул временных результатов с отдельной арендой при вложенных эффектах, spatial broad-phase с последующей исходной точной проверкой и исходным порядком результата. Physics2D не является механически точной заменой: могут измениться порядок совпадающих целей, границы столкновения, момент рождения/смерти и RNG. Burst/Jobs — только для независимых расчётов над снимком, с применением результата в исходном порядке.

### P2 — синхронная запись сохранения и перезагрузка при запуске

`Runtime/EchoSphereRunPersistence.cs:91–155`; `Core/RunSnapshotCodec.cs:34–79`; `EchoSphereNativeRegions.cs:48–63`.

Метаданные reflection и части снимков уже кэшируются. Однако создаются SavedRun/SavedEntity, JSON-строка, обходятся сущности, затем на главном потоке вызывается PlayerPrefs.Save. Автосохранение срабатывает после накопления 1 секунды **ограниченного delta ≤.05**; при тяжёлом лаге это не обязательно раз в реальную секунду. Во время туториала путь отключён и его первоначальные лаги этим не объясняются.

Выбор региона синхронно сохраняет флаги и LoadScene заново инициализирует сцену. LoadSceneAsync с управляемой активацией — кандидат для отзывчивости загрузки, не автоматическое устранение стоимости Awake/ресурсов. Для сохранений сначала отделить стоимость snapshot/JSON/flush; любые atomic-file/background-write решения отдельно проектировать с сохранением схемы, очередности и гарантий pause/quit. PlayerPrefs уже является API Unity; универсального штатного сериализатора всей игры с прежним контрактом нет.

### P2 — оставшаяся стоимость меню, памяти и первого входа

`Presentation/NativeCharacterScreen.cs:45–63,132–163`, `NativeCharacterArtwork.cs:10–34`, `NativeMenuArtwork.cs:17–20,64–86`, `NativeMenuBrushCache.cs:10–49`.

Портреты списка загружаются асинхронно по viewport, но все карточки UI всё ещё создаются при Build; это ограниченный список из десяти, не бесконечная лента. Невидимые NativeHudSurface не готовят рисунок. Выбранный портрет Home/игрока имеет синхронный Resolve на cache miss. Static portrait cache удерживает загруженное. У spherist default compression=0, Android override выключен, mipmaps включены, Read/Write выключен. Это риск памяти/первой загрузки; реальный формат и resident bytes новой APK не измерены. Сжатие с потерями без визуальной приёмки не включать.

Перерисовка персонажей держит opacity=0 до двух следующих кадров после изменения модели. При низком FPS кадровая задержка превращается в секунды; это механизм усиления задержки, не доказательство причины конкретных пяти секунд.

Кандидаты: предварительная async-загрузка выбранного портрета, управляемая резидентность; ListView с динамической высотой только если создание/память карточек реально существенны (сохранить раскрытие и scroll). Статичное меню-ядро всё ещё использует собственные SourceUiDepth и SourceUiSurfaceFilters через typed native entry, без CSS parser. Его Prepare dirty-gated, а не выполняет все GPU-проходы постоянно. Возможно вынести неизменяемые рисунки в импортируемые ассеты/VectorImage/9-slice, сохранив DPR и края. Не объявлять все градиенты/тени штатными стилями без сравнения.

`NativeEngineBackdrop` уже использует нативный backdropFilter. Собственными остаются Gaussian material, параметры и контроль видимости. Его проверка видимости не проверяет scroll-viewport; реальные offscreen passes должен подтвердить UI Toolkit/Frame Debugger, так как клиппинг может выполнить движок.

### P2 — предупреждение Android-шейдера

Завершённая сборка сообщила possible uninitialized variable (Blur) в `SourceUiSurfaceFilters.shader:16` на GLES3/Vulkan (также dx12). Текст функции явно инициализирует result/total; без воспроизведения нельзя назвать это доказанным чтением мусора или причиной телефона. Активный native consumer — blur блика меню через NativeMenuArtwork. Проверить минимальный случай/выход шейдера на целевых API; не исправлять вслепую алгоритм по формулировке предупреждения.

## Остаток миграции: решение по системам

| Система | Фактический статус | Решение |
|---|---|---|
| Меню, HUD, модальные окна, ввод | UI Toolkit, UXML/USS, pointer events | Уже нативно; не переписывать |
| Стекло | Native backdropFilter + custom Gaussian | Владение уже Unity; сохранить точный эффект, проверить расходы |
| Боевой compositor/RT | Собственный orchestration на Unity API | Кандидат URP RenderGraph/RendererFeature; крупная работа |
| Меши сфер, врагов, позы | Unity Mesh + Vector Graphics + C# | Сохранить арт; переносить только доказанно тяжёлое построение |
| Короткоживущие объекты | GameObject create/destroy | ObjectPool — прямой практический кандидат |
| Декоративные частицы/следы | Собственная симуляция + native mesh drawing | ParticleSystem/TrailRenderer — условно, при точной визуальной и save parity |
| Мир-текст | Unity Font/TextGenerator + retained mesh | TMP/TextCore кандидат унификации, не обязательная миграция; метрики/атлас уже кэшируются |
| Каталоги/иконки | Native catalogs, VectorImage, Resources | Уже Unity; Addressables/SpriteAtlas только под доказанный lifecycle/batching сценарий |
| Снимок игры | JsonUtility + custom capture + PlayerPrefs | Оптимизация архитектуры хранения, не «замена на Unity» |
| Формулы/RNG/сеть/боевые правила | Типизированный C# Core | Оставить; Physics2D/ECS не эквивалентная замена |
| Старый V/VisualJs/DOM/Canvas/replica UI | Editor-only, Android guard в UnityTypeChecks | Не источник Android-кадра; очистка исходников отдельно |

ParticleSystem — предпочтительный первый эксперимент для декоративных эффектов. VFX Graph нельзя назначать общей заменой для текущего Vulkan/GLES3 набора: OpenGL ES им не поддерживается. В проекте потребуется проверить/подключить соответствующие пакеты для любых новых модулей.

## Порядок следующей работы

1. Проверить свежую APK на прежних сценариях: эффект последнего исправления UI-теней ещё не принят на Xiaomi. Не смешивать исправление с новым набором изменений.
2. Ограничить финальное смешивание world-shadow областью тени; проверить все blend modes и края, отдельно считать composite passes.
3. Убрать невидимую подготовку мира, внедрить ObjectPool и reusable network projection. Проверить lifetime/save/порядок событий.
4. Прототип URP RenderGraph на существующем арте, без пересоздания игрового Core. Оставить только при измеримом выигрыше и визуальной идентичности.
5. Затем частицы/геометрия, меню-residency, запросы целей и сохранение — по стоимости на новом билде.

Узкая полоса при запуске остаётся OPEN. Размеры world texture, logical viewport, panel scale и UI worldBound устанавливаются разными участками; CSS native-field и compositor оба имеют предел 1280×800. Это не доказанное постоянное рассогласование аспектов. Нужна имеющаяся frame/layout-трасса именно телефона. Доказательств одновременного browser/native GPU-рендера не найдено.
