0A. REVISION 1.2 — QUALITY / SYSTEMIC ALIGNMENT AMENDMENT
======================================================================

This amendment is part of the authoritative Blueprint and takes
precedence over older wording inside this document when a conflict exists.

PURPOSE:
The September 25 quality audit identified several places where the
implemented game systems were mechanically simpler than the intended
product identity. The target is NOT to reduce the final design scope.
The target is to make the existing core systems more readable,
meaningful and internally consistent.

1. CONTACT DAMAGE

Contact damage must not behave as frame-by-frame HP shredding.

RULE:
- after successful player damage, apply 0.60 sec post-hit grace;
- this grace is separate from Dash invulnerability;
- repeated contact during grace does not deal additional damage;
- visual feedback must communicate the hit and short protection window.

This rule applies to enemy contact and repeated close-range collision
sources routed through the same player-damage function. It does not
remove projectile danger or boss telegraphed attacks.

2. CRITICAL HITS

Final baseline:
CRIT_BASE = 5%
CRIT_MULTIPLIER_BASE = 1.50x
CRIT_HARD_CAP = 75%

All ordinary crit sources are additive before the hard cap.
Sphere-specific bonuses may add to the same pool.
A system that intentionally bypasses the cap must be an explicit
exception in its own specification.

3. RESONANCE MODEL

Resonance is a real run resource, not merely per-Sphere hit counters.

AUTHORITATIVE TARGET:
- 0..100 baseline charge;
- charge comes from Sphere hits, completed Geometry, network events,
  character effects, Artifacts and selected Runes;
- reaching 100 triggers a formation-specific Resonance Event;
- temporary overflow to 150 is allowed only through explicit effects.

Per-Sphere counters may remain as implementation details for local
formation triggers, but they must not replace the player-level Resonance
resource in the final architecture.

4. ARTIFACT SET COMPLETION

Completing an Artifact Set must change gameplay behavior.
A flat universal damage multiplier is NOT a valid Set-completion effect.

Current intended behavioral direction:

RESONANCE GRID:
completed Set accelerates formation-driven Resonance events.

ECHO ARCHITECTURE:
completed Set creates real relay events between linked Spheres.

SINGULARITY PATH:
completed Set creates a conditional high-risk execution/echo behavior
when the build is intentionally concentrated.

Set completion must remain visible in the UI and readable as a build
milestone.

5. ELITE ENEMIES

An Elite is not only a larger HP/damage unit.

At least one Elite family must interact with the game's core system.
The first implementation target is LINK BREAKER:
- periodically targets a nearby Sphere;
- temporarily removes that Sphere from active Network participation;
- clearly telegraphs the disruption;
- creates a meaningful reason to reposition or protect the Network.

Future Elite families may target Resonance, Geometry or resource flow.
Do not create many Elite mechanics before the first one is playtested.

6. LEVEL-UP RNG QUALITY

Level-Up choice generation remains the core build-construction engine.
The final model explicitly requires:
- build affinity;
- character affinity;
- unfinished-system pressure;
- duplicate suppression;
- dead-option suppression;
- pity weighting;
- rarity/reward-source rules;
- limited reroll;
- Lock;
- later-meta Ban.

The player must never be guaranteed a specific build item, but should
also not be trapped by repeated functionally dead choices.

7. SEEDED RUN RNG

Gameplay randomness must use the run RNG state.
Renderer-only cosmetic jitter may remain non-deterministic.
A run should be reproducible when the same seed and equivalent inputs are
used, which is important for balance debugging and future telemetry.

8. NETWORK READABILITY

Network topology is the game's defining mechanic.
Any feature that changes Network structure must have:
- immediate visual feedback;
- readable active/inactive state;
- clear indication when a Sphere loses Network participation;
- enough persistence that the player can understand what happened.

Ghost Snap is now an approved UX direction for Sphere repositioning:
while moving a Sphere, show a preview of the resulting links and likely
Geometry before the player commits the placement.

9. FORMATION MEMORY

When a Sphere is removed, disrupted or repositioned, the player should
be able to understand which formation was broken and which formation can
be rebuilt. This may be implemented as a short-lived ghost outline,
link fade or Geometry echo.

10. PERFORMANCE GUARDRAIL

analyzeSphereNetwork() is gameplay-critical and may be called by many
systems. The implementation must be profiled before optimization.
If profiling confirms redundant same-frame recomputation, use a
frame/run cache rather than rewriting the Network algorithm blindly.

11. SCOPE DECISION

This amendment does NOT cut the final target roster.

Preserve:
- 10 Sphere types;
- 7 Geometry states;
- 90-120 Artifact target;
- 15+ enemy roles;
- 8 boss families;
- full Character target;
- long-term meta systems.

Development is phased, but the Blueprint remains the full target.
Scope reductions may be made only from actual playtest evidence,
production constraints or a deliberate product decision, not from an
external reviewer's arbitrary launch-scope recommendation.

12. DEVELOPMENT ORDER AFTER THIS AMENDMENT

P0:
- contact damage cadence;
- crit normalization;
- Resonance architecture alignment;
- Network disruption readability.

P1:
- Ghost Snap placement preview;
- Formation Memory;
- Artifact Set behavioral polish;
- first Link Breaker Elite playtest.

P2:
- Level-Up RNG protections;
- Network performance profiling/cache if justified;
- deeper Elite/Network interactions;
- broader Artifact and Geometry content.

1. DESIGN REFERENCE: MAGIC SURVIVAL
======================================================================

Magic Survival is used only as a benchmark for systemic depth and
long-term buildcraft.

Research consulted during validation:
- unofficial Magic Survival wiki, current pages crawled in September 2026;
- Magic, Artifact, Class, Research and Basics pages;
- community build references and mechanics notes.

The benchmark shows the value of:
- separate combat and passive progression layers;
- repeated level-up decisions;
- persistent Class/Research progression;
- Artifact rewards independent from level-up;
- Synergy created by collections of Artifacts;
- merchants and rerolls;
- special field pickups;
- rare legendary reward moments;
- build-specific value changing over time;
- explicit formulas and community theorycrafting.

The benchmark also confirms that its RNG is a real build-construction
constraint: Level Up normally offers three random choices, existing
choices are weighted, some systems can create four choices, and Artifact
rewards can also be rerolled in specific contexts.

ECHO SPHERE does NOT copy:
- names;
- characters;
- art;
- lore;
- UI layouts;
- descriptions;
- exact abilities;
- exact Artifact designs;
- exact progression tables.

Instead, ECHO SPHERE keeps the structural lesson and makes NETWORK +
GEOMETRY + RESONANCE its own core system.

Benchmark facts and source references are listed in Appendix A.

3. PLAYER EXPERIENCE
======================================================================

The player must:
- understand movement immediately;
- survive without manual aiming;
- make frequent but understandable choices;
- feel that Sphere placement matters;
- recognize build direction;
- adapt to RNG without waiting for one perfect item;
- read enemy danger;
- understand boss attacks before damage lands;
- feel major reward moments;
- understand death;
- want another run.

The intended sensation is:
EARLY:
"I am building."
MID:
"My network now behaves differently."
LATE:
"I engineered this build on purpose."

======================================================================

NORMAL RUN:
15-20 minutes.

EXTENDED RUN:
20-30 minutes.

ENDLESS:

Design target:

Boss cadence:
- first major boss approximately 5-6 min;
- second major boss approximately 10-12 min;
- final encounter approximately 15-20 min.

======================================================================
17. NETWORK
======================================================================

Every active Sphere is a Network Node.

A Link is active when:
distance <= LINK_DISTANCE
and both nodes are alive.

Current repository uses a pixel-space implementation around 220 px.
The final design treats this as a configurable gamefield distance,
not a fixed real-world measurement.

Base target:
LINK_DISTANCE = 220 logical field units.

Each Link has:
- endpoints;
- distance;
- strength;
- resonance state.

Network statistics:
- node count;
- link count;
- average link distance;
- density;
- stability;
- active geometry;
- Resonance charge.

48. DAMAGE MODEL
======================================================================

Base damage is separated into categories.

FinalDamage =
BaseDamage
× SphereMultiplier
× ModifierMultiplier
× NetworkMultiplier
× ArtifactMultiplier
× ResonanceMultiplier
× CritMultiplier
× CharacterMultiplier

Not every effect is multiplicative.

Stacking policy:
- same-family small bonuses generally add;
- category-level bonuses may multiply;
- character signatures use explicit category;
- critical multiplier is applied only on a successful crit;
- diminishing returns apply to extreme haste, radius and density.

No uncontrolled chain of multiplicative bonuses.

======================================================================
49. COOLDOWN MODEL
======================================================================

FinalCooldown =
BaseCooldown
× LocalModifier
× AbilityModifier
× CharacterModifier
× ArtifactModifier
× NetworkModifier

Hard floor:
20% of BaseCooldown.

Temporary exceptions may bypass the floor for a short effect.

Every override must be explicit in data.

======================================================================

source
interaction flags.

- Fracture = reaction state.

Alchemist can create:

Reactions consume participating statuses.

======================================================================
52. NETWORK BALANCE
======================================================================

Define:

DENSITY =
activeLinks / maxPossibleLinks

At high density:
diminishing returns.

Suggested:
D <= 0.60
full efficiency.

0.60 < D <= 0.80
90% incremental efficiency.

D > 0.80
70% incremental efficiency.

This keeps compact networks good without making "stack everything in
one point" the dominant answer.

5. What Artifact changed my plan?
6. Which Synergy/Protocol matters?
7. Which boss mechanic forced adaptation?
8. What will I change next run?

If the answer is only:
"I got more damage,"
the design failed its depth target.

If the answer is:
"I built a Chain Triangle network, used Resonance to relay attacks,
then got a Legendary that made Cluster valuable, so I moved my Spheres
and changed Protocol,"
the core identity is working.

APPENDIX A. MAGIC SURVIVAL BENCHMARK FACTS
======================================================================

The following are reference facts used to validate architecture, not
instructions to copy the game.

A1. LEVEL UP
The researched wiki documents a standard 3-choice Level Up flow, with
previously acquired Magic receiving increased selection weight and some
systems enabling 4 choices.

A2. MAGIC LAYERS
The researched Magic page separates combat/active Magic from passive
enhancement Magic and also documents special enhancement Magic.

A3. CLASS
Classes modify preferred Magic and possess unique mechanics; the wiki
also documents persistent class progression whose highest upgrade can
apply beyond the currently equipped class.

A4. SUBJECT / EXPERIMENT BODY
The benchmark uses a separate visual/character-like layer that can grant
a starting Artifact and persistent effects. ECHO SPHERE uses Character +
Cosmetic Core Skin instead of copying this structure literally.

A5. RESEARCH
The researched current Research page documents 96 total Research points
and multiple permanent stats including attack, HP, XP, cooldown, movement,
pickup range, size, duration, choice count, Rune duration and loot.

A6. ARTIFACTS
Artifacts can be obtained from treasure, wave-related structures and a
merchant. Normal Artifact caches present three choices. Legendary
reward structures are separated from ordinary Artifact acquisition.

A7. SYNERGY
Artifact Synergy activates automatically when all required Artifacts are
owned, and one Artifact may participate in multiple synergies.

A8. RUNES
The researched Basics page documents Runes as temporary field pickups
that trigger special effects immediately. It documents examples for:
attack/movement boost, invulnerability, pickup-range boost and field
enemy clearing.

A9. MERCHANT
The researched Basics page documents a merchant with multiple Artifact
offers, a discounted random offer, rising prices over appearances and a
limited active window.

A10. ECONOMIC LOOP
The benchmark uses in-run Mana Orbs for XP and merchant purchasing, plus
persistent currencies including Gold/Gems and persistent Research/Class
progress.

A11. FORMULAS
The researched FAQ documents a multiplicative final-damage structure
involving attack power, attack-power amplification, spell coefficient,
damage bonuses/reductions, class additions and critical multiplier.
For ECHO SPHERE this is inspiration for category separation, not an
instruction to copy exact coefficients.

A12. TIME-VARYING VALUE
Community build guides explicitly discuss Artifact value changing with
time, build state and remaining reward opportunities.
ECHO SPHERE therefore treats build context, run timing and diminishing
opportunity as first-class balance concerns.
