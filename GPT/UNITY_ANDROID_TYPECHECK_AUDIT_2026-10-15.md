# Повторный аудит Unity-переноса, типов и Android

Источник: `new-desing`, `737ef2af4a877e0995db5f92331d536d2f29a934`.
Начальное состояние этого этапа: `unity-migration`, `48eb07e`.
Unity Editor и Unity-сборки не запускались. Редактор пользователя находится на другом компьютере.

## Что теперь проверяется компилятором

Прежний синтаксический аудит не проверял типы Unity API. Для этого этапа из
[официального дистрибутива Unity 6000.3.24f1](https://unity.com/releases/editor/whats-new/6000.3.24f1)
извлечены настоящие DLL движка, профиля .NET и кэша Universal-шаблона. Редактор
не устанавливается и не исполняется. Загружаются только шесть независимых
XZ-блоков, около 39 MiB; SHA-256 всех 387 DLL зафиксированы в
`tools/EchoSphere.UnityTypeChecks/reference-manifest.json`.

Roslyn компилирует код в память с C# 9. Заглушки Unity API не используются.

## Найденные и исправленные ошибки

Начальная семантическая проверка обнаружила три настоящие ошибки игрового C#:

1. Прямое присваивание `Color32` свойству `StyleColor`: требуется преобразование в `Color`.
2. Запись `scene["player"]["sphereMovementLocked"]` через временную структуру `V`.
3. Запись `choices[index]["nativeIndex"]` через временную структуру `V`.

В двух последних случаях изменяется тот же исходный объект, но через локальную
переменную, допустимую для компилятора C#. Значения и действия не заменены.

Также устранены 225 предупреждений о недостижимых запасных `return default` в
генераторе: запасной return теперь добавляется только при возможном достижении
конца функции. Сгенерированные файлы повторно получены из неизменённого TS/TSX.
Потоки команд, экраны и анимационные проверки сохранены. Общее подавление CS0162
из portable VisualChecks удалено.

Устаревшие `VisualElement.transform`, `MeshWriteData.uvRegion`,
`EventBase.PreventDefault` и Android `BuildTargetGroup`-перегрузки заменены
соответствующими API Unity 6.3. Поля JSON-моделей имеют явные прежние значения по
умолчанию; два неиспользуемых поля удалены. При выбранном Android target в
Windows Editor системные шрифты и emoji теперь ищутся для ОС редактора, а
Android-плеер продолжает использовать Android-семейства.

## Android и IL2CPP

Bootstrap явно задаёт IL2CPP, .NET Standard, ARM64 вместе с сохранённым ARMv7.
Минимальный SDK не опускается ниже API 25, соответствующего
[требованиям Unity 6000.3](https://docs.unity3d.com/6000.3/Documentation/Manual/android-requirements-and-compatibility.html).
Уровень установленного target SDK не подменяется произвольным значением.

Существующий `Assets/EchoSphere/link.xml` с сохранением Core/Runtime/Presentation
оставлен: reflection используется не только проекцией, но и сериализацией
снимков забега. Сужать эту защиту без проверки настоящего IL2CPP-плеера было бы
риском для сохранений. Размер APK после stripping этим этапом не измерялся.
Поиск FieldInfo для полей игрового состояния кэшируется.

Для всех UI-filter проходов с целочисленным индексом прямоугольника задан
shader target 3.5. Это проверка конфигурации GLES3/Vulkan, а не выполненная
компиляция шейдеров. Preflight также контролирует Android backend, архитектуры,
профиль API, linker-preservation и прежнюю ошибочную зависимость textrendering.

## Оптимизации без изменения исходного рисунка

- Удалён полный `FindObjectsByType<Renderer>` на каждом кадре. Игровая камера
  исключает неиспользуемые сценические рендереры; исходный Canvas остаётся
  текстурой UI Toolkit.
- Старые `EnemyCreatureVisual2D` и `SphereRuntimeVfx2D` не создают и не
  пересобирают скрытые меши при активном исходном renderer. Данные варианта
  врага и игровой симуляции сохранены.
- JNI-плотность экрана кэшируется до изменения размеров/DPI экрана.
- Canvas повторно использует MaterialPropertyBlock и передаёт диапазоны
  индексов меша без создания отдельного списка для каждого draw batch.
  Пустые пакеты не рисуются; три промежуточных буфера теней выделяются только
  при наличии рисуемой тени в кадре.
- Пустые CSS-кисти полностью прозрачных контейнеров имеют один прозрачный
  пиксель вместо полноразмерных рабочих массивов и текстур. Размеры layout,
  дочерние элементы, текст и прокрутка не уменьшаются. Проверяется также
  отсутствие видимых пикселей в соответствующем браузерном эталоне.
- В CSS-растеризаторе удалены массивы расстояний и разворот коллекции на каждом
  пикселе; порядок смешивания сохранён. Буферы внутренних теней выделяются
  только при наличии inset-тени.

Измерение одного непрозрачного CSS-фона 360×800 в portable .NET-проверке:
**63 411 536 → 10 410 376 байт** управляемых выделений, примерно на 83,6% меньше.
Это измерение одной операции на CPU .NET, **не** снижение общей памяти игры или
измерение FPS Android. Дополнительно проверяется прозрачный контейнер
2000×12000 при DPR 3: его собственная кисть занимает один прозрачный пиксель.

Размытия, порядок слоёв, размеры видимых ресурсов и качество изображения ради
производительности не уменьшены. Браузерные проверки кистей проходят с прежним
максимумом средней ошибки 1,373/255; число сравниваемых пикселей уменьшилось
только для полностью прозрачных собственных кистей.

## Вывод и границы проверки

Перенос остаётся нативным C#/UI Toolkit/RenderTexture, без WebView и JS-движка.
Активный источник визуала — транслированные `new-desing` renderer/TSX/CSS;
исходные `src/`, `public/`, package/lock и TypeScript-конфиги не изменены.
Найденные ошибки типов и перечисленные проблемы исправлены. Новых конкретных
пропусков визуала в просмотренных путях не обнаружено.

Это не подтверждение отсутствия всех предупреждений настоящего Unity Editor.
Не выполнялись Unity package resolution/import, Unity-specific analyzers,
компиляция шейдеров, IL2CPP conversion, Android SDK/NDK build и запуск на GPU.
Компиляция C# с настоящими API-сборками подтверждена отдельно и не заменяет эти
этапы. Итоговые шрифты, Yoga-layout, GPU-композиция, жизненный цикл на устройстве,
память и FPS требуют ручной проверки Unity/Android. Основные оставшиеся затраты,
которые нужно измерить профайлером, — тесcеляция исходных путей и размытия;
придумывать упрощения эффектов для обхода этой проверки не стали.
