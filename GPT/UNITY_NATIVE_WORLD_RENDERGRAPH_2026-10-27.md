# Боевой мир: раннее отсечение и URP RenderGraph

2026-10-27, `unity-migration`, исходный HEAD `5a1e51ff2547512c6ef5b76e5feb579305b867dd` (CI #875 SUCCESS).

## Реализовано и включено

1. **Раннее отсечение тел врагов до подготовки геометрии.** Сначала обновляется Facing/Travel/AnatomyTime/Motion, затем проверяется консервативная область текущего тела, конечностей, крыльев, хвоста, свечения, статусов и значков. Для текущих процедурных моделей применяется envelope `4r+32` до root transform: наибольшее свечение 2.55r, цепочки костей/хвосты <3r, запас покрывает минимальные детали и текущие stroke miters. Матрица камеры/дрожание/scale/rotation и полное наследуемое ядро тени учитываются в NativeWorldSurface.IntersectsLocalBounds. Невалидные границы консервативно рисуются.
2. Дальние линии элитных врагов, boss signals и nameplates **не отсекаются по телу**. Они остаются отдельными вызовами с собственным существующим отсечением готовых команд. Поэтому телеграф может пересечь экран, даже если его хозяин находится далеко за краем. Их дополнительное раннее отсечение ещё не реализовано.
3. **Обычный боевой кадр выполняется внутри URP RenderGraph.** NativeWorldSurface строит типизированные команды, а NativeWorldRenderGraphFeature записывает их в граф камеры перед post-processing. Смешивание мира и финальная копия в UI texture попадают в command buffer URP; отдельные Graphics.ExecuteCommandBuffer / Graphics.Blit этого мира больше не выполняются в обычном активном кадре. Текущие меши, шейдеры, цвета, порядок прозрачности, размер буферов и MSAA сохранены.
4. Native feature привязывается к конкретной камере/владельцу. Renderer data изменяется только в памяти через публичные API; собственные feature instances удаляются при уничтожении владельца. Файлы URP/Quality/package assets не сохраняются. Дублирующиеся ссылки renderer data не добавляют второй проход. При первом подключении/снятии производится однократная инвалидизация renderer; её Android-стоимость ещё не измерена.
5. World/UI RenderTextures импортируются через RTHandle без передачи владения. При изменении размеров обёртки освобождаются перед собственными текстурами. Глифы готовятся перед фактической записью команд, чтобы не использовать устаревший атлас после запросов другой камеры. View/projection/viewport и camera color target восстанавливаются в конце прохода.
6. На возврате в меню снимается pending world frame. При отсутствии готового URP-владельца, в Edit Mode/паузе Editor и диагностических сравнениях остаётся немедленный путь. Это fallback, а не параллельное рисование одного мира.
7. Bounded development frame journal теперь включает graph pending/pass count/last frame и отдельные счётчики composite/culling. Это поможет проверять очередность первого кадра на устройстве без покадрового бесконечного журнала.

## Фактическая граница переноса

Исполнение кадра перенесено в нативный URP RenderGraph и включено в основной runtime. Собственная организация процедурной геометрии и исходного draw order сохраняется. Используется **один unsafe graph pass**, так как внутри остаются переключения targets, global shader state, точные blend modes и существующие временные shadow RT. Это стандартный публичный RenderGraph API, но граф пока не управляет каждой временной тенью отдельно и не может объединить эти подоперации в raster passes. Нельзя называть эту группу завершением всей оптимизации RenderGraph.

Копия world → UI texture сохранена для действующего контракта UI Toolkit. Удалять её без отдельного сравнения цветов, прозрачности, ориентации и порядка UI нельзя. Общая симуляция, RNG, формулы, коллизии, частота сохранений и механики не менялись.
